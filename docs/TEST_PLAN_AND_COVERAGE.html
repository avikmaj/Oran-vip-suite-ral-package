1 · Verification strategy

Each component is modelled at the 64-bit protocol-header transaction level with a single spec.json descriptor (field widths, legal space, cross-field constraints, coverage bins) driving all lanes. Stimulus is constrained-random: the legal space and corner weighting come from the protocol spec, never from hardcoded values; the same seed reproduces a run exactly. Coverage is coverage-driven — coverpoints trace to vplan features, holes are closed by directed constraints then reverted. Five executed test classes per component:

2 · Traceability model

FR-### (requirement) → FEAT-### (feature) → VC/TC-### (test case & class) → SEQ-### (constrained-random sequence) → COV-### / CHK-### / SVA (coverage bin & checker) → BUG-### (if a failure is found).
Each per-component table below realises this chain: every field yields a FEAT (legal-space + legality checker + coverpoint), every cross-constraint yields a FEAT + cross-coverage + SVA invariant, plus pack/round-trip and reset features.
